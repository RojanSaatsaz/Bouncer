1

Why consent matters for Bouncer

Listening counts

Bouncer doesn't record calls. But it hears and transcribes them live, and some wiretap laws (like California's) cover eavesdropping, not just recording.

Cal. Penal Code § 632

11 + 2 states

11 states require everyone on a phone call to agree to being listened to or recorded. Connecticut and Michigan are mixed or unclear, so we'd treat them the same way.

Federal law and most states need only one party's consent (18 U.S.C. § 2511(2)(d)).

The other party

The user agrees when they sign up and merge Bouncer in. The other person on the call (the scammer, or a real bank or relative) hasn't agreed. That's the gap an announcement closes.

AI listeners are a live legal question: Ambriz v. Google (N.D. Cal. 2025).

2

Call-consent rules by state

For phone calls. When the two people are in different states, plan on the stricter state's rule applying: California's top court applied its all-party rule to calls with Californians made from Georgia (Kearney v. Salomon Smith Barney, 2006).

Who has to agree to a call being heard

All parties (11) Mixed or unclear: treat as all parties (2) One party (37 + DC)

Reading the map

All parties: California, Delaware, Florida, Illinois, Maryland, Massachusetts, Montana, Nevada, New Hampshire, Pennsylvania, Washington.

Mixed or unclear: Connecticut (civil law requires all parties on calls, criminal law only one); Michigan (the statute reads all-party, but courts have let participants record).

Watch: Oregon is one-party for phone calls but all-party for in-person talk. Washington treats a clear announcement that is captured with the call as consent (RCW 9.73.030(3); confirm the exact text).

Lists differ between sources (10–13 states). This is a planning snapshot; counsel should confirm each state before launch.

3

Consent checker (concept)

Before Bouncer starts listening, a checker decides whether its first words should be a short announcement. Try it: pick how Bouncer joined, the user's state, and (only when the carrier can share it) the other party's area code.

Call in progress · 3 peopleBouncer just joined

How it would plug into Bouncer

  1. At call start: ElevenLabs can call our server before a call connects (the conversation-initiation webhook; the route and its secret, BOUNCER_INIT_TOKEN, already exist). The server looks up the caller and returns the announcement as the agent's first message, or none. Overriding the first message per call has to be turned on in the agent's settings; confirm in ElevenLabs docs.
  2. Merged calls: Bouncer can't see the other number on a merged call today, so the other party is "unknown" and the checker announces. Carrier-level access could supply the other leg's number and let one-party-to-one-party calls stay silent.
  3. Area codes are hints, not locations: numbers move with people and can be spoofed. The checker only skips the announcement when every signal points to one-party states, and announces when anything is missing.
  4. After the announcement Bouncer goes silent again and texts warnings as it does today. If the caller hangs up on hearing it, that's a win too.

Separate text and call lines against spoofing

Caller ID is easy to fake. An iMessage thread isn't: it's tied to the user's own device and Apple ID. So Bouncer keeps talking and telling on two different numbers, and anything private or any action only ever goes through the user's own registered text thread.

📞Call line +1 617-993-9248

  • Listens silently; speaks only after "Hey Bouncer".
  • Two sentences at most, and never a safe word, account detail, address or other personal info. It says "I've sent that to your phone."
  • Can't take any action by voice: a scammer on the call can say "Hey Bouncer" too.

💬Text line +1 628-998-8619

  • Verdicts, warnings, recovery steps, and private info all go only to the registered user's own thread.
  • Every action (calling a relative, alerting family) needs a YES typed in that thread.
  • The family safe word is texted only to the protected person, in their own thread, and only when they ask.

6

Signing up without the Photon dashboard

Today

Each user's phone number or Apple ID is added as a sender and assigned to Bouncer's shared iMessage line in the Photon dashboard. Only after that can they text Bouncer, because a shared line can't text anyone first.

Sign-up link (possible now)

  1. User opens a link (QR code in a T-Mobile store, a text from T-Mobile, or the T-Life app) and enters their number.
  2. Our server calls Photon's assignment API, POST /v1/projects/{id}/platforms/imessage/assignments with { handle }, which returns the assigned number. This needs an API key with platforms:write; ours has read only.
  3. The page shows "Text hi to Bouncer at …" plus a contact card with both numbers, and the welcome flow takes over.

Limits: shared lines have a per-project cap (the API can return SHARED_LINE_CAP_EXCEEDED), and confirming a number belongs to the person (a code or link sent to it) should come first.

Sign-up by text

Not on the shared iMessage line: as far as we can tell from Photon's docs, a shared line only reaches us from assigned senders, so a stranger's "JOIN" never arrives. Worth confirming with Photon.

Possible options:

  • SMS "JOIN" to the call line, if SMS is turned on for that number in Photon; the server assigns them and replies with the text line's number. Unverified.
  • A dedicated iMessage line (Photon's paid mode), where anyone can text Bouncer directly with no assignment step.
  • At T-Mobile scale: turn Bouncer on from the T-Mobile account (app or store), with T-Mobile provisioning the number.
